# Adversarial publication audit — 2026-09-12

The local application and its public-source build pass the verification described below. Publication has deliberately not been performed. Remote GitHub Actions/Pages success and physical Ubuntu kiosk acceptance remain separate checks.

## Method and scope

Three independent review passes covered the pure game/runtime, contracts/build/security, and component/content UX. Integration review then exercised hostile timing sequences, invalid inputs, clean installation, real static files, the portable HTML, Pages paths, accessibility, licensing, and the new Ubuntu deployment scripts. Findings were corrected and relevant regressions were added before revalidation.

This is an engineering audit, not a penetration-test certification, formal proof, trademark clearance, or accessibility conformance certificate. No participant information or private organisation assets were used.

## Remaining acceptance and limitations

- The maintainer will push the source. Enable the GitHub Actions Pages source and `PAGES_ENABLED=true`, then verify the remote workflow and live URL as described in [publication](publishing.md).
- The Ubuntu kit targets a dedicated Ubuntu 24.04 Server. It has not been boot-tested in a fresh Ubuntu VM or on the intended kiosk. Validate the actual PAM/logind, GPU, Snap policy, boot/crash recovery, SSH recovery and keyboard behavior before leaving it unattended. It does not promise a universal modifier/Fn/right-click whitelist. See [Ubuntu setup](ubuntu-kiosk.md).
- Browser automation is Chromium-based. Human keyboard/screen-reader, zoom, touch, language comprehension and target-hardware checks remain necessary. The guided duration is a design target, not a measured promise for every participant.
- A Pages host can process connection metadata even though the application has no telemetry. Meta CSP cannot enforce a framing policy; host response headers are a separate deployment concern. Private logos in customised artifacts are intentionally public to anyone receiving those artifacts.
- Brand-name availability and future campaign-logo use require their own review. No institutional logo is included. See [legal notes](legal.md).
- Completed situations keep their first outcome and cannot be replayed in the same session. Reset starts a fresh game; there is no participant report or stored score export.

The locally reviewed source is suitable for the maintainer's first GitHub push with these explicit limits. Passing local checks does not assert that the remote deployment or physical kiosk has already been accepted.
